# Crossly — External Dependencies and Owner Follow-up Register
Purpose: keep a permanent list of work that cannot be completed safely with code alone. Update this file whenever a feature reaches an external credential, commercial approval, real-world business decision, legal review, or infrastructure dependency.
Security rule: NEVER paste API keys, passwords, tokens, private certificates, OTP secrets, card data, or production credentials into this file or source control. Store only the provider/service name, responsible owner, status, and secret-manager reference.
Status meanings:
- REQUIRED: owner access or decision is still needed.
- READY_TO_CONNECT: access exists and the software adapter can be connected.
- CONNECTED_NOT_LIVE: technically connected but production activation is not approved.
- LIVE: production approval and verification are complete.
